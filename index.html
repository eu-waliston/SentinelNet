// Sobre o projeto

Indicadores isolados contam apenas parte da história

O SentinelNet é uma plataforma experimental de Cyber Threat Intelligence (CTI) que identifica relacionamentos entre diferentes indicadores de infraestrutura, construindo uma visão contextual para auxiliar investigações e mecanismos defensivos.

🌐

Domínios & DNS

Registros A/AAAA, CNAME, MX, NS, histórico de resolução e alterações de infraestrutura.

DNS collector
🌍

IP & ASN

Endereços IP, ASN, organização, relacionamento entre infraestrutura e concentração de domínios.

IP intelligence
🔐

Certificados TLS

Fingerprints, emissor, validade, Subject, SANs e compartilhamento de certificados.

TLS analysis
📋

WHOIS / RDAP

Informações de registro, datas, registrador e entidades associadas quando disponíveis.

Registration data
🌐

Metadados HTTP

Headers, redirects, status codes, tecnologias identificáveis e metadata.

HTTP metadata
🕸️

Grafo de infraestrutura

Relações entre infraestruturas com confidence score, permitindo representar o grau de confiança das associações.

Correlation
🧠

O SentinelNet não substitui a análise humana. O sistema fornece evidências, correlações e indicadores para auxiliar processos de investigação e defesa.

// Arquitetura

Coleta, normalização, correlação e análise de risco

A V1 segue um pipeline modular que separa claramente a coleta de dados, a extração de características, a correlação e o cálculo do risco — permitindo evoluir cada camada de forma independente.

Fontes de dados
DNS / HTTP / TLS
→
Data Collector
→
Feature Extraction
→
ML Classifier
Graph Correlation
Anomaly Detection
→
Risk Engine
→
Decision / Review

🐢 Backend

Node.js + TypeScript, Fastify/Express, MongoDB, Redis e REST API. Responsável por entidades, ingestão de eventos, armazenamento, correlação e execução do Risk Engine.

🐍 Machine Learning

Serviço separado em Python com scikit-learn, XGBoost, NetworkX e PyTorch. A separação evita transformar o backend Node.js em um "Frankenstein tecnológico".

🖥️ Frontend

React + TypeScript + Vite. Dashboard operacional com lista de indicadores, Risk Score, grafo de infraestrutura, timeline e visualização de evidências.

// Correlation Engine

De um indicador isolado a uma rede de conhecimento

O problema central é identificar que diferentes indicadores aparentemente independentes fazem parte da mesma infraestrutura ou apresentam comportamento semelhante.

🔎 Análise tradicional

example.com
      ↓
185.x.x.x

🕸️ Análise SentinelNet

                         ┌── Certificate A
                         │
example.com ──→ IP ──────┼── ASN 12345
                         │
                         └── Domain B
                              │
                              └── IP 185.x.x.x

Modelo de relacionamentos

Cada relacionamento possui uma confidence, permitindo representar o grau de confiança da associação.

{
  "source": "example.bet",
  "target": "185.x.x.x",
  "type": "RESOLVES_TO",
  "confidence": 0.98
}
RESOLVES_TO USES_CERTIFICATE BELONGS_TO_ASN SHARES_INFRASTRUCTURE REDIRECTS_TO
// Risk Engine

Um número isolado não explica nada

O Risk Engine transforma evidências em indicadores de risco — e, mais importante, armazena as evidências que contribuíram para sua composição. Isso permite responder "por que esse indicador recebeu esse score?".

📊 Composição inicial (rule-based)

DNS similarity        +15
Infrastructure link   +20
Certificate link      +15
ASN correlation       +10
Behavior anomaly      +20
Known bad relation    +20
                      ────
                       100

// Princípios do projeto

Como o SentinelNet é construído

O desenvolvimento segue princípios claros que orientam cada decisão técnica e cada linha de código.

🔍 Evidence First

Toda classificação deve ser acompanhada de evidências.

🧠 Explainable Intelligence

O sistema deve explicar como chegou a determinado resultado.

🕸️ Relationship Driven

Indicadores isolados contam apenas parte da história.

🛡️ Defensive by Design

O projeto é orientado para defesa e análise autorizada.

📈 Incremental Development

Cada módulo deve funcionar antes da próxima camada ser adicionada.

🤖 AI as a Tool

Machine Learning deve ampliar a capacidade analítica, não substituir a validação dos dados.

// Roadmap

Nove módulos incrementais

O projeto será desenvolvido de forma incremental, com cada módulo funcionando antes da próxima camada ser adicionada.

Módulo 1 — Core

Arquitetura inicial, TypeScript, API, MongoDB, modelos de dados, entidades, eventos, health check e configuração de ambiente. ← foco atual

Módulo 2 — Threat Intelligence

DNS collector, IP/ASN intelligence, certificados TLS, WHOIS/RDAP, metadados HTTP, normalização e armazenamento dos indicadores.

Módulo 3 — Correlation Engine

Modelo de relacionamentos, construção do grafo, correlação de infraestrutura, descoberta de infraestrutura compartilhada, confidence score e histórico.

Módulo 4 — Risk Engine

Sistema de regras, Risk Score, evidências, confidence, priorização e explicabilidade.

Módulo 5 — Machine Learning

Dataset, feature engineering, feature selection, treinamento, validação, classificação, API de inferência e XGBoost/Random Forest.

Módulo 6 — Anomaly Detection

Baseline de comportamento, detecção de alterações DNS, mudanças de infraestrutura, novos relacionamentos, anomalias temporais e alertas.

Módulo 7 — Dashboard

Dashboard operacional, lista de indicadores, Risk Score, grafo de infraestrutura, timeline, página de investigação e visualização de evidências.

Módulo 8 — Blocking Integration

Geração de listas, exportação de indicadores, DNS filtering, proxy integration, firewall integration e API de integração — sempre em ambientes sob controle ou autorização do operador.

Módulo 9 — IA Avançada

Correlação automática, classificação contextual, explicação dos resultados, priorização de investigação, graph-based ML, modelos híbridos e assistência à análise.

// Segurança e uso responsável

Defensivo por design

O SentinelNet é desenvolvido exclusivamente para defesa cibernética, análise de infraestrutura, Threat Intelligence, pesquisa, detecção de anomalias, monitoramento autorizado e integração com mecanismos defensivos.

✓ O que o projeto É

  • 🛡️ Defesa cibernética e análise de infraestrutura
  • 🔍 Threat Intelligence e pesquisa
  • 📡 Detecção de anomalias e monitoramento autorizado
  • 🔗 Integração com mecanismos defensivos
  • 📂 Fontes públicas, autorizadas ou controladas

✗ O que o projeto NÃO é

  • 🚫 Exploração de sistemas de terceiros
  • 🚫 Comprometimento de servidores
  • 🚫 Realização de ataques
  • 🚫 Contorno de mecanismos de proteção
  • 🚫 Ações ofensivas não autorizadas
⚠️

O bloqueio ou mitigação deverá ocorrer apenas em ambientes sob controle ou autorização. O SentinelNet não tem como objetivo explorar, comprometer ou derrubar infraestrutura de terceiros.
